# Dining Philosophers with Semaphores (C++20) — "The Living Table"

Files: `main.cpp`, `dining_philosophers_semaphore.html` (generated by running `main.cpp`), `README.md`.

## Build and run
```bash
g++ -std=c++20 -O2 -pthread -Wall -Wextra main.cpp -o dining   # needs g++ 11+ or clang 14+ with libstdc++ 11+
./dining                  # 3 rounds, writes dining_philosophers_semaphore.html
./dining 5 out.html 42    # optional: rounds, output file, random seed
./dining --selftest       # feeds the validator a deliberately corrupted trace
```
Then open the HTML file in any browser (no server, CDN or internet needed). Every run produces a different trace, because thread scheduling differs; the HTML is a replay of *that* run. The program exits with 0 only if all invariants held.

## Algorithm
* 4 philosopher threads, 4 `std::binary_semaphore` forks (initial 1), 1 `std::counting_semaphore<3>` room (initial 3).
* Fork *i* lies between philosopher *i* and *i+1*; philosopher *i* uses left fork `(i+3)%4` and right fork `i`.
* Loop per philosopher: think → hungry → `room.acquire()` → `fork[left].acquire()` → `fork[right].acquire()` → eat → release both forks → `room.release()`.

| Semaphore | Initial | Purpose |
|---|---|---|
| `fork[i]` | 1 | 1 = on table, 0 = held. Only one owner at a time, so **mutual exclusion**. |
| `room` | 3 | At most 3 philosophers compete for forks at once. |

**Why the room prevents deadlock.** Deadlock needs circular wait: all 4 philosophers each holding one fork and waiting for the next. With at most 3 inside, at least one philosopher holds nothing, so at most 3 forks are "one-in-hand" and a 4th fork is free. Some philosopher inside can take it, eat, and release, so the system always makes progress.

**Starvation.** Deadlock-free is not starvation-free. `std::counting_semaphore` gives no FIFO guarantee, so one philosopher could in theory keep losing the race for the room or a fork. In practice, short runs show every philosopher eating, but nothing in the code *guarantees* it. A fair queue (ticket or FIFO semaphore) would.

## How the trace is recorded
`Recorder::log` takes a mutex, assigns `seq` and a timestamp inside the lock, and appends the event, so there is one total order. Acquisitions are logged as an attempt (`*_REQ`/`ROOM_TRY`) before `acquire()` and as a success (`*_OK`) after it returns; releases are logged *before* `release()`. So logged ownership is never longer than real ownership, and a correct run cannot look wrong (or the reverse). The browser rebuilds the full state at event *k* by replaying events 0..*k*.

Event types: `THINK, HUNGRY, ROOM_TRY, ROOM_OK, FORK_REQ, FORK_OK, EAT_START, EAT_END, FORK_REL, ROOM_REL, DONE`.

## Validation (read-only replay of the trace)
Exactly 4 philosophers/forks; no fork with two owners; no adjacent eaters; eating only with both adjacent forks; every acquisition released; room never above 3; all 4 threads reach `DONE`; legal per-philosopher state order. Results appear in the console and in the HTML panel. Violations are shown, never hidden.

## Animation controls
Play/Pause, Reset, Step ← / →, speed (0.5x–4x), slider (seek), click any row in the timeline. Keyboard: Space, ← and →. Gold ring = acting philosopher / fork of the current event. Dashed coral line = pending fork request. The centre of the table shows room permits and who is blocked.

## Testing actually performed (Ubuntu 24.04, g++ 13.3, 1 machine)
* Compiled with `-std=c++20 -O2 -pthread -Wall -Wextra`: no warnings.
* 30 consecutive runs (5 rounds each): all exited 0, all 8 checks passed, every philosopher ate every round.
* ThreadSanitizer build, 3 runs: no warnings.
* `--selftest`: the validator flagged 7 of the 8 checks on a deliberately corrupted trace. The check "4 philosophers and 4 forks exist (all ids in range)" is not triggered by that trace, because it contains no out-of-range ids.
* HTML opened in headless Chromium (Playwright): no JavaScript errors; step, back, reset, play and seek worked; no horizontal scrolling at 390 px width.
* Not tested: Windows/MSVC, Safari/Firefox, real touch devices.
